# CORE → ARE smoke test

This is the first opt-in migration slice. It runs the original `computations_1`
task in ARE, using CORE's existing arithmetic implementation. ARE owns the app,
scenario, event ordering, and tool log. CORE's unchanged saved-trace evaluator
scores the resulting path. The driver is an ARE oracle script, **not an LLM**.

## Run

From this checkout:

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements-are.txt
.venv/bin/python -m are_integration.smoke --output /tmp/core-are-smoke.json
```

The command succeeds only if ARE executes both actions in order, returns 22 and
66, reaches the expected app state, exports both calls with arguments, and the
legacy CORE scorer returns 1.0. The evidence file includes the full converted
run artifact, evaluator result, and individual check results. No provider key is
needed. The scorer is the existing legacy path scorer; this does not reproduce
all five CORE paper metrics or establish LLM task success.

To make the scenario discoverable by ARE's CLI, install this checkout in editable
mode from the repository root after installing the dependencies:

```sh
.venv/bin/python -m pip install -e .
.venv/bin/are-run -s core_computations_1 -o
```

The oracle CLI command checks ARE registration and scenario execution. The
`are_integration.smoke` command above additionally checks CORE trace conversion
and scoring.

## One live ARE agent (paid)

Put `OPENAI_API_KEY="..."` in this checkout's ignored `.env`, or export it in
the shell. Then run from the repository root:

```sh
.venv/bin/python -m are_integration.live
```

This uses ARE's default text-action agent and OpenAI `gpt-4.1-nano`. The dedicated
runner makes at most six model requests, caps each response at 256 tokens, sets a
30-second request timeout, and disables SDK retries. Use `--max-requests`,
`--max-output-tokens`, or `--model` to change those limits. It runs one ARE user
turn. The output path printed at the end contains `run.json` with the actual
agent tool path, CORE legacy score, validation, usage, and limits, plus ARE's raw
trace JSON. A failed task or an unscored trace is saved as evidence, not hidden.

The first paid run on 30 September 2026 used `gpt-4.1-nano` and made three model
requests. The agent called `add_numbers(15, 7)` and then
`multiply_numbers(22, 3)`. ARE validated the final calculation state (66), and
CORE's legacy path scorer returned 1.0. The agent's final user-message call had
an invalid argument type, so no final reply was delivered. `are_success` reports
the computation-state validation; it does not establish successful reply delivery
or reproduce all five CORE paper metrics. The local raw trace and converted run
artifact are saved under `runs/are/computations_1/` and ignored by Git.

ARE's `--provider openai` in version 1.2.0 selects a Hugging Face client; this
runner instead provides ARE's agent with a directly configured OpenAI engine.

## Where CORE plugs into ARE

| CORE | ARE | Owner in this slice |
|---|---|---|
| `Computations` methods and world state | `CoreComputationsApp` tools and state | `are_integration/computations.py` |
| `computations_1` prompt and reference calls | `CoreComputationsOne` user event and oracle events | `are_integration/computations.py` |
| Tool call sequence | ARE `Environment.event_log` | `are_integration/smoke.py` and `are_integration/live.py` |
| DFA alphabet and legacy path score | Existing `function_calling.evaluation` | Unchanged |

The adapter reads only ARE **agent** events from the CORE app. It retains the
actual call order, arguments, results, error status, ARE event ID, and event
time. User and environment events are kept out of CORE's agent path. The oracle
run is a reference execution fixture. The live runner uses the same adapter on
events generated by an ARE agent.

## Next gates

1. **Parity:** Run the same reference calls in original CORE and ARE and compare
   state, return values, tool names, arguments, and path score. Add a reversed
   call order and an extra harmful call to verify that trace conversion preserves
   mistakes. Do not silently drop failed or unmapped calls.
2. **Live completion:** Review the first live run's invalid final-message call.
   Track reply delivery separately from state validation and path scoring.
3. **Stateful world:** Migrate a small world with setup and read/write behavior
   (for example CRUD) to test reset isolation, setup events, and read calls.
4. **Coverage:** Create a world/task inventory and move through the 13 worlds in
   this checkout. Track Farm/Arm separately because their paper implementations
   are absent here. Repair known source defects as explicit, reviewed changes.
5. **Paper metrics and comparison:** Reproduce all five CORE metrics from ARE
   traces, then compare ARE prompting and vanilla function calling on matched
   scenarios, tools, model versions, call limits, and seeds. Report task success
   separately from path scores.

For the broader experiment, ARE is the runtime and event source; CORE's DFA and
metrics remain the process evaluator. Gaia2's write-action verifier is a separate
evaluation signal and must not replace CORE's full-path scoring, which counts
read calls and harmful attempts as well.
